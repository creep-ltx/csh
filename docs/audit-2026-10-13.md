# csh 0.1b3 audit (2026-10-13)

Four readers covered the whole of `src/` and `tools/ls.c`. **C** = confirmed: ASan on the PC with `tests/fakeos.c`,
measured with `-fstack-usage`, or re-checked in the code by a second reader. **R** = read only, not run.
Nothing was changed by the audit. `make test` was green before it (57 + 119).

**Fixed in 0.1b4 (the same evening)**, see "What 0.1b4 did" at the end: every item of the first table and
of "Wrong behaviour", except the few listed there as left. Note: finding "CTerm answers in res2" was
wrong - res2 is right (Guru Book 21.2.4.3); the bug was csh's (it read res1).

## Wrong behaviour

Language (lang.c):
- `$(exit 3)` / `( exit )` quit the whole line, and at the prompt **quit csh**; return/break leak out of `$( )` too (C).
- `a=$(false); echo $?` gives 0: `if out=$(cmd)` is always true (C).
- `"$@"` with no arguments is one empty word (C).
- `alias ls='ls -F'; ls x` runs `ls -F -F -F -F x` (C); alias arguments are re-parsed after Amiga quoting (`e '$HOME'` expands) (C).
- A pipe stage's first word is expanded twice: `$(c) | Sort` runs c twice (C); stages after the 16th silently dropped (C).
- `${u:-'a b'}` keeps the quotes; `"${x:-"a b"}"` gives garbage; `)` inside `$( case ... )` ends it early. Two quote scanners disagree (C).
- `#(a|b)` / `~(...)` are a syntax error, against the decided rule (C).
- `1>&2` syntax error; `2>/dev/null` not mapped to NIL: (C).
- Here-docs: delimiter on the last line without LF, `f() { cat <<E; }`, `\"` (C).
- A failed redirection on `{ }`, a function or an alias is ignored and the body runs (R).
- `aborted` cleared only in lang_line: after a Ctrl-C in a `#!csh` script run from Amiga rules, later scripts silently do nothing (R).
- Errors and `set -x` go to the current output (pipes, files, `$( )`), not the console (C).
- `fi`, `done` alone run as Amiga commands (C).
- `local` / prefix assignments put an ENV: value back as a local copy that shadows it (R).

Running commands (run.c, job.c, main.c):
- An Amiga script (s-bit, Execute) from the csh language runs **after the whole line**: `myscript && echo ok` prints ok first, `$(myscript)` captures nothing, in `for` they run reversed (R).
- `#!csh` / RX script as the last pipe stage doesn't get the pipe as input (R).
- A background job ending overwrites `$RC` and the prompt's rc (bash leaves `$?`) (R).
- Result2 of the wrong stage kept after a pipe (R).
- `$0` changes after a script calls another (static `path`) (R).
- Ctrl-C between script lines is cleared, never acted on (the ROM stops the Executes); Ctrl-D cleared where the ROM doesn't (R).
- `csh FROM x` inside a ROM Execute script zeroes the outer `cli_CommandFile`: its T: file stays, FailAt reset (R).
- PIPE:/T: names restart at 1 per csh: a nested csh or a left-behind job can join the wrong pipe; `$( )` in a nested csh collides with `T:csh-cap-N-1` and captures nothing (R).
- Lines ≥ 1023 split into two commands (R).
- **CTerm** console.c:1100 answers ACTION_CHANGE_SIGNAL with the old port in res2, con-handler in res1: csh "restores" port -1 (R, both sources).

Built-ins / os.c / line.c:
- `echo I want to go` goes to the ROM's Echo (any word `to/first/len/noline`), which writes to a file named `go` (C).
- `alias foo bar=baz` defines `bar` (C).
- `export X=1` after `X=0` leaves 0 (local wins); `unset X` leaves the exported one (R).
- **`[ -d "" ]` and `[ -e "" ]` are true** (`Lock("")` is the current dir): `[ -d "$UNSET" ]` true (R).
- `[ "(" = "(" ]`, `[ "$x" = "!" ]` fail (C).
- printf: `%s` cut at 256, `\NNN`, `\0NNN`, `\c` wrong, bad number rc 0 (C).
- `<>a >b` / `<>a <b` mix the files up (C); `cmd >` with no name silently no redirection (C).
- `read -s a` makes a variable `-s` (C).

Prompt (edit.c, term.c, comp.c, hist.c, keys.c) and ls:
- Lines over ~430 coloured characters drawn cut off, cursor rows wrong (C).
- Multi-line prompts break the redraw; a last output line without LF is erased by the prompt (R).
- History between tabs: lines skipped, wiped by the rewrite, overwritten by interleaved appends, or shown empty mid-write (R).
- Ctrl-C does not stop a multi-line paste; CRLF paste leaves `\r`; a missing end-of-paste marker swallows all typing forever (R).
- First/Last history keys: stale prefix length, Last does nothing (R).
- Completion only quotes names with a space (`;|(#$*` go in bare) (R).
- Command table stops at 768 names (they show red); only the first drawer of a multi-assign C: (R).
- Writes to ENVARC (history, keys, FileColours) without `pr_WindowPtr = -1`: requesters on a write-protected boot disk, every 20 lines (R).
- `ls` stops at the first error (`ls nosuch README`, `-R` past one unreadable drawer); names with `( [ | ~` are taken as patterns; `-l` Dir column misaligned for tiny files (R).

## Speed

- Every simple command, even `true`, allocates ~4 KB in two arena blocks cleared twice (cmdline + alias buffer) - ~1 ms at 14 MHz. Allocate the cmdline only for Amiga commands.
- Every key in the command word can `Lock()` (unknown words, `:` or `/`): slow on floppy/network, `CD0:` starts the handler. Result thrown away for the word being typed.
- With a grey suggestion showing, every key redraws the whole prompt + line.
- First Tab after a command reads up to 400 KB of its file byte by byte; never notices an updated command.
- `term_open` waits up to 1 s per prompt for a console that doesn't answer the size query; `ls` 0.5 s.
- An unset `$var` costs two GetVar (local, then ENV: packet).
- lang_line re-parses all pending text on each continuation line (quadratic for a long paste); glob sort is insertion sort.
- s-bit scripts are read 2-3 times (isscript, source, RX check).
- History rewritten to ENVARC every 20 lines (~40 KB each, per tab).

## Tests that cannot see these (tests/fakeos.c differs from os.c)

One variable store (no local/ENV: split), `os_redir` never fails, `os_test("")` false, glob uses sh patterns not Amiga ones,
`os_tty` goes into captures, `os_tempfile` / `os_delete` / `os_break` are stubs. Every bug above marked C fits straight into
`tests/lang_test.c`; the fakeos gaps should be closed so the R ones can be tested too.

## The good

- Arenas in lang.c: one free per line / command / function; ASan found no leaks on normal paths. Loop bodies and functions parsed once.
- line.c: every append bounded, the 1020-1022 byte limits exact at the edge.
- `run_seg` restores streams, pr_CES, program name, PROGDIR, cli_Module symmetrically; resident counts under Forbid; csh never caches cli_CurrentInput; every exit path reaches `job_leave`.
- `os_redir` / `os_capture` balanced, capture file deleted even after Ctrl-C, console never closed.
- Key decoding bounded and careful; output gathered into one Write; ExAll handled right in ls.
- Command table hashed, rebuilt only when a drawer's date changes; requesters off around Locks in comp.c.
- Ctrl-C polled at every node; `local` frames undone on every exit path; brace expansion bounded.

## The meh

- Static buffers in run_cmd/run_line/test: not re-entrant (the `$0` and FailAt-name bugs come from this).
- echo/alias/set hand-off to the ROM keyed on keywords anywhere in the line.
- printf and arithmetic are subsets (no `%f`, `<< >> & | ^ ?: **`, assignments).
- Error message formats and rcs differ between built-ins (`csh: source needs a file` vs `printf: ...`; failed redirection 10 for built-ins, 20 for commands).
- Dead code: `os_rom`, `run_text`'s `top`, `char *v[1]` in shift, a duplicated comment in run.c.

## What 0.1b4 did (2026-10-13)

Checked: `make test` 61 line + 171 language checks (ASan), every bug above that the PC can show has a
check in `tests/lang_test.c` / `tests/line_test.c`; in FS-UAE the 12 ROM pairs are byte for byte the same,
and `tests/lang/fixes.csh` shows on the real ROM: an Amiga script runs in order (`myscript && echo`,
`$(myscript)`, in `for`), export/unset reach ENV:, `[ -d "" ]` false, errors stay out of `$( )`,
`tc_SigAlloc` unchanged after 25 nested pipes (0.1b3: one bit lost a run and Ctrl-C's bit freed, measured
with `tests/probe/sigs`), `ls -R` 12 drawers deep on a 4 KB stack, `ls` going on past a missing name, a
`#!csh` script reading a pipe.

How, in short:
- `$1..` belong to each function call and sourced script (their own arena); a function redefined while
  running is freed when its last call ends; arithmetic has depth limits (a variable naming itself);
  every function call, `$( )`, alias and source checks the stack left (`os_stackleft`), and the big
  frames (run_simple, pipeline, for, case, block redirections) are out of `exec`'s.
- One scanner for quotes and `$( )`/`${ }` for the lexer and the expander (a `case` inside `$( )`
  too); `${x:-'a b'}` takes the quotes off; `"$@"` with nothing is no word; `$( )` and `( )` keep exit,
  return, break inside them; `a=$(cmd)` gives cmd's rc; aliases do not expand themselves and get their
  arguments quoted for csh; `1>&2`, `/dev/null` is NIL:, `#(a|b)` and `~(x)` stay patterns; `fi` alone is
  a syntax error; here-documents: last line without LF, inside a function, `\"`; pipes up to 32 (said
  past that); a failed redirection stops a block, function or alias (rc 20, as run.c).
- `export` writes ENV: and drops the local copy; a later `x=1` of an exported name writes ENV:; `unset`
  deletes an exported one there; `local` and `X=1 cmd` give back only a local value.
- Errors and `set -x` go to the error stream (2>, else the console), never into a pipe or `$( )`.
- printf rewritten (`%.500d` printed, not buffered; `%s` whole; `\NNN`, `\xHH`, `%b`, `\c`; rc 10 on a bad
  number); test reads three words as `a OP b` first; read refuses unknown options and long lines whole;
  shift/break/return say a bad count; echo goes to the ROM's Echo only for NOLINE, FIRST n, LEN n, TO
  (capitals) file; `alias a b=c` is the ROM's.
- job.c: the child's PROGDIR lock put back; the relay port's own signal bit freed and the task's
  tc_MemEntry made a list; ACTION_CHANGE_SIGNAL's res2 read; jobs left running at exit no longer Signal
  csh or write to its console handle (their own `*`); Ctrl-C twice while waiting sends the job to the
  background; a job ending leaves `$RC`; Result2 of the right stage; T: names any number, all names
  carry the CLI number and this csh's address (nested csh, jobs left behind).
- run.c/main.c: an Execute from the csh language runs its lines at once (`script_now`); `csh FROM` in an
  Amiga script leaves that script's T: file and FailAt; lines too long are refused, not split; script
  paths of any length; Ctrl-D no longer cleared before commands (the ROM clears C, E, F).
- Memory at exit: functions, `$1..`, pending text, exported names, the command table, templates,
  history, C:'s locks, the paste - all freed (0.1b3 left ~45 KB a tab).
- The prompt: colours never cut the line (they stop first); multi-row prompts; a command's last line
  without LF gets a line end before the prompt (CSI 6n); a redraw sends only what changed (a key with
  the grey suggestion showing costs a few bytes); no disk asked about the word being typed, a few words'
  kinds remembered, a sleeping device (DF1:, CD0:) never woken by colouring; a console that never
  answers the size question is not asked again; pastes: tabs and control bytes cleaned, CRLF one line
  end, Ctrl-C drops the rest, a missing end mark ends after 2 s; Ctrl+R hands its last key on;
  First/Last keys fixed; `#[` `#(` not coloured as comments.
- History between tabs: appends under an exclusive lock in one Write, a tab that sees another wrote
  reads again, the file is shortened from its own contents (not one tab's memory), an empty file
  mid-write is ignored.
- comp.c: the command table grows (no limit of 768), every drawer of a multi-assign C:, the template
  cache cleared when a drawer changes, 160 KB read at most, names quoted for every csh character, no
  overflow on long paths.
- Files csh and ls write (history, keys, prefs, FileColours) put no requester up.
- ls 0.2: recursion on the heap with a stack check; goes on past errors; a name that is there is a
  name even with ( [ | ~; `-l` Dir column.

Left on purpose (and why):
- Ctrl-C between the lines of an Amiga script is cleared, as the ROM Shell does (it clears C/E/F
  before each command); only Ctrl-D stops a script.
- `RAM: foo` (a drawer with arguments) still CDs - the ROM's rule is not checked yet.
- An unset `$var` still asks ENV: (bash sees the environment too); a cache would go stale.
- lang_line parses all pending text again for each continuation line (only long pastes notice).
- ls swallows keys typed during its 0.5 s width question when $COLUMNS is not set (csh sets it).
- tests/fakeos.c's glob is sh-style, the Amiga's is AmigaDOS patterns.
- Not yet tried on the A1200 or in CTerm: the prompt changes. Tried by hand in a plain Shell window in
  FS-UAE (wasabi keys and grabs): output without LF gets its line before the prompt, a two-row prompt,
  the grey suggestion, editing inside a long wrapped coloured line, Ctrl+R then an arrow key. Pastes
  (CTerm's marked paste) not tried yet.

Measured in FS-UAE (`Avail FLUSH`, csh started in a Shell window, Tab, `ls`, exit; three rounds):
0.1b3 left 28.8 KB each round, 0.1b4 32 bytes - the ROM Shell's own history line. Speed
(`tests/bench.sh`, csh/ROM): vars 0.74, loop 0.97, pipe 1.00; the csh language 0.61 / 0.09 / 1.00
(0.1b3: 0.64 / 0.10 / 1.01).
